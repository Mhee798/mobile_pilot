# เตรียม UI จริงของ MobilePilot

## ทางเข้าระหว่างพัฒนา

`lib/main.dart` กำหนด `useDebugUi`: ค่า `true` เปิดหน้าตั้งค่า Accessibility และหน้าทดสอบเดิม; ค่า `false` เปิดโครงหน้าจริงที่ยังอยู่ระหว่างพัฒนา หน้าจริงยังไม่ได้เชื่อมแชท เครื่องมือ หรือการตั้งค่า การสลับต้อง rebuild/restart แอป ค่า flag นี้เป็นตัวเลือก UI ไม่ใช่การตรวจว่าแอปเป็น debug หรือ release build และไม่ได้เป็นกลไกรักษาความปลอดภัย

## สิ่งที่ต้องเตรียมก่อนเชื่อมหน้าจริง

1. **สถานะงานร่วม:** กำหนดสถานะกำลังคิด ใช้เครื่องมือ รอผู้ใช้ ตอบเสร็จ หยุด ไม่สำเร็จ และยังยืนยันไม่ได้ ให้หน้าแชทกับตัวลอยใช้แหล่งข้อมูลเดียวกัน แสดงเฉพาะผลที่ระบบสังเกตได้
2. **ตัวควบคุม Gemini Cloud:** แยกการจัดการบทสนทนา คำสั่งเครื่องมือ การเลือกแอป และสถานะงานออกจาก `GeminiTestPage` เป็น `GeminiChatController` แล้ว หน้าทดสอบยังเป็นเจ้าของ controller และปิดงานเมื่อออกจากหน้า; ก่อนทำแชทจริงที่อยู่ต่อได้ระหว่างเปลี่ยนหน้าต้องกำหนดเจ้าของและอายุของ controller ในระดับแอปเพิ่มเติม
3. **ประวัติแชทและงาน:** กำหนดว่าจะเก็บบทสนทนาจริงอย่างไรแยกจากประวัติวินิจฉัยที่มีอยู่ รวมถึงการสร้างแชทใหม่และสลับแชทโดยไม่ทิ้งงานที่กำลังทำ
4. **การตั้งค่าและสิทธิ์:** ให้เข้าแชทได้แม้ยังไม่เปิด Accessibility แต่แสดงสถานะและชวนเปิดเมื่อจะควบคุมเครื่อง; จัดการ Firebase, โมเดล, ไมค์, ภาพหน้าจอ, เสียง และการแจ้งเตือนให้มีสถานะชัดเจน
5. **ทางลัด:** ออกแบบข้อมูลและการบันทึกลำดับเครื่องมือ พร้อมแยกจากทางลัดที่ส่งคำสั่งให้ AI ปัจจุบันยังไม่มีตัวแก้ไขหรือ replay runner ที่บันทึกถาวร
6. **แชทและหน้าลอย:** วางโครงเมนูด้านข้าง แชทเต็มจอ ช่องพิมพ์เหนือคีย์บอร์ด ตัวเลือกแอป และสถานะงานที่หยุดได้; ทดสอบไม่ให้ตัวลอยบังจุดที่ต้องแตะ
7. **ตรวจบนมือถือ:** ทดสอบ Markdown, การเลือกคัดลอก, ไมค์และวงแหวน, เสียงอ่านภาษาไทย, คีย์บอร์ด, จอเล็ก และขนาดตัวอักษร รวมถึงงานต่อเนื่องตอนสลับแอป

## งานที่เริ่มเชื่อมแล้ว

- มี `AiTaskPhase` สำหรับสถานะหลักที่ local และ Gemini Cloud ส่งเข้า controller ร่วม แต่หน้าจริงและตัวลอยยังต้องปรับให้แสดงจาก phase นี้แทนข้อความเดิมทั้งหมด; `responded` ยืนยันเฉพาะว่ามีคำตอบ ไม่ใช่งานสำเร็จ
- หน้าทดสอบ Gemini บันทึกข้อความที่คุยสำเร็จใน Hive CE บนเครื่อง เปิดแชทเก่าและส่งข้อความที่แสดงเป็น context ต่อได้ โดยไม่กู้ภาพหรือ tool calls; ประวัติวินิจฉัยเดิมยังแยกต่างหากและเชื่อมด้วย run IDs ข้อมูล Hive รุ่นนี้ยังไม่ได้เปิดการเข้ารหัส
- รูปแบบ Hive รุ่นแรกเขียนทั้งบทสนทนาทุกครั้งที่มีคำตอบ และอ่านรายการแชทพร้อมข้อความ จึงควรแยก metadata/ข้อความพร้อมวางแผน migration หากประวัติเริ่มมีขนาดใหญ่
- เครื่องมือที่พบว่า service ใช้งานไม่ได้จะตรวจ Accessibility เพิ่มและส่ง `ACCESSIBILITY_DISABLED` เฉพาะเมื่อระบบรายงานว่าปิดอยู่ หน้าทดสอบ Gemini และโมเดลในเครื่องแสดงปุ่มเปิดตั้งค่า; การทำ flow ดังกล่าวในหน้าจริงยังต้องเชื่อมต่อ
- ทางลัดเก็บ Hive CE และรองรับการหน่วง/ลูปเป็นแผนในอนาคต ยังไม่มี editor หรือ runner

Gemini Nano ผ่าน AICore ไม่รองรับการคิดต่อเมื่อ MobilePilot ไม่ใช่แอปหลัก ต้องสื่อข้อจำกัดนี้ในหน้าตั้งค่า Gemini Cloud ส่งข้อมูลที่จำเป็นไปยัง Google และต้องแสดงเรื่องการส่งภาพให้ชัดเจน
